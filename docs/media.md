# 图片与文章自动识别

已开启的同步群收到图片或支持的文章分享后，群历会自动读取内容，提取活动，再使用现有的校验、去重和飞书写入流程。无需把海报文字复制到工作台，也无需启用远程模型。

## 一次配置，后台处理

图片识别在独立 Python 环境中运行，需要 RapidOCR（ONNX Runtime 版）、Pillow 和 NumPy。推荐使用 Python 3.12 安装：

```bash
/usr/bin/python3 scripts/install_ocr.py
```

脚本会在 `~/.local/share/wechat-feishu-calendar/ocr-venv` 安装 `requirements-media.txt`，不需要管理员权限。首次安装需要联网下载依赖及其附带的模型文件；识别过程不发送图片到云端。

已有兼容环境时，可以直接指定解释器：

```bash
export CALENDAR_OCR_PYTHON="/path/to/ocr-venv/bin/python"
python3 -m app
```

启动后台服务时，环境变量需要写入 `systemctl --user edit wechat-feishu-calendar.service` 的 `[Service]` 段。自动查找顺序为：显式指定的解释器、当前数据目录中的 `ocr-venv`、项目中的 `.venv-media`、本机已有的 `~/repository/linux-wechat-rpa/.venv`。显式指定后不回退到其他环境。

自定义数据目录时，可用 `CALENDAR_APP_DATA=/path/to/data /usr/bin/python3 scripts/install_ocr.py` 安装到对应目录，并以 `python3 -m app --data-dir /path/to/data` 启动。微信读取桥继续使用 `WECHAT_CLI_DIR` 下原有的 `.venv`，其中需要 PyCryptodome；App 不修改其他项目的环境。

## 微信图片如何读取

1. 从选定群的精确消息编号读取图片元数据。
2. 使用消息中的原图 MD5 查询微信本机附件索引，并校验所属群。不会选择附件文件夹中的随机图片，也不会把缩略图当作原图。
3. 支持原始图片、旧式单字节 XOR `.dat`、V1 和已验证的 Linux 微信 V2 附件格式。
4. V2 候选密钥由当前账号目录标识和本机 `kvcomm` 文件名中的数值推导，在读取子进程中使用；不读取进程内存，不需要 root，不返回或保存派生密钥。
5. 解密后校验完整图片 MD5，再交给本机 OCR。校验失败时不读取其他附件替代。

识别格式包括 JPEG、PNG、GIF、WebP 和 TIFF。附件上限 20 MB，OCR 分辨率上限 2500 万像素；多帧图片只处理第一帧。支持范围取决于本机微信版本和附件格式，新格式可能需要适配。

微信必须已将匹配的原图保存到这台电脑。群历会在原图落盘后继续识别，但不会操作微信界面下载附件，也不会访问受登录保护的 CDN 下载接口。附件尚未就绪时会显示“后台自动重试”。

## 支持哪些文章

| 来源 | 读取方式 | 当前范围 |
| :--- | :--- | :--- |
| 微信公众号 `mp.weixin.qq.com` | 读取公开正文与标题 | 正文没有完整日程时，继续对正文前 6 张受支持图片做本机 OCR |
| 云就业 `m.bysjy.com.cn` / `s.bysjy.com.cn` | 读取分享页面对应的公开宣讲详情 | 提取网站实际公布的开始、结束时间和地点，不补造活动时长 |

文章内图片仅从 `mmbiz.qpic.cn` 和 `mmbiz.qlogo.cn` 下载。链接必须使用 HTTPS；域名、端口、DNS 公网地址和每一次跳转均检查。读取不携带浏览器 Cookie，不执行网页脚本。

需要登录、访问验证、被删除的文章和未支持的网站保留原因供核对。下载体积超过处理上限时保留原因供核对；图片超过 6 张时，已经读到的内容保留为候选并标明限制，避免无限重试。小程序、合并转发、语音、视频、文件正文暂不解析。

## 自动添加和重试规则

- 明确、未结束且识别置信度足够的通知，按群设置自动添加到目标日历。一个通知中的多个活动分别生成日程。
- OCR 采用文字行最低置信度；低于 0.90 的结果保留为待确认，避免低质量文字直接写入。这个分数来自 OCR，并不是日程语义正确性的保证，日期、时间和地点仍接受独立校验。
- 缺少时间、日期与星期冲突、取消、改期、超出读取上限及已结束活动保留识别内容与具体原因，不自动发布。
- 附件尚未下载完整、暂时不能解密或网络暂时失败，会按 30 秒、1 分钟、2 分钟等逐步退避，最多间隔 30 分钟重试。没有新聊天消息时也会检查到期重试任务。
- 暂停群会暂停后台识别和重试。明确忽略的消息保持忽略，即使识别任务正在运行也不会恢复处理。
- 可以随时点击“重新识别”或“立即重试”；沿用原消息编号与原日程请求编号，避免重复创建。
- 历史预览仍只扫描文字通知。新媒体流程作用于开启同步后接收的消息；已经进入待确认的图片可直接重新识别。

识别结果可在“同步记录”的“详情”中查看来源、原图和识别文字，文章候选附带原文链接。手动工作台仍可用于修正信息，但不是自动识别的必要步骤。

## 数据留在哪里

解密原图与 OCR 结果保存在 App 私有数据目录的 `images/` 中，目录权限为 `0700`、缓存文件为 `0600`。运行数据库保存识别文字、来源、结果和重试时间。图片预览仅由本机 App 提供，不加载外部图床。

图片 OCR 不依赖可选模型。开启模型辅助时，仍遵循设置页面对单条通知的发送规则；默认保持关闭。读取公开文章本身会访问相应网站。写入飞书的内容包括活动信息、文字备注和文章原文链接，不上传海报原图。

运行数据库、原图、OCR 缓存、聊天标识和授权信息都不应提交到 Git。仓库中的测试与截图使用虚构示例。

## 格式参考

本地解码实现参考以下项目公开说明的附件布局与候选密钥推导方式，采用独立实现，并额外要求消息、群、文件索引与完整 MD5 匹配：

- [ChatTrace · image_key.py（MIT）](https://github.com/qiaodogbear/ChatTrace/blob/main/src/chattrace/service/image_key.py)：Linux 微信 `kvcomm` 文件名与账号标识的候选密钥推导。
- [wechat-decrypt · decode_image.py（MIT）](https://github.com/328336690/wechat-decrypt/blob/main/decode_image.py)：V1/V2 图片头、AES 分段与 XOR 尾段格式。
- [RapidOCR](https://github.com/RapidAI/RapidOCR)：本机文字检测与识别组件。依赖及模型以各自许可证为准。

V2 解码不使用消息 XML 中的 CDN AES 密钥作为本地 `.dat` 密钥；只有完整图片校验通过的内容才进入 OCR。
